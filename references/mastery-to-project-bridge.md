# Mastery To Project Bridge

Use this after the teaching layer when the user wants to apply the book.

## Conversion Principle

Only convert ideas that the user now understands. A method card built from a misunderstood concept becomes a dangerous shortcut.

## Outputs

### Method Cards

Each method card must include:

- method name
- source anchor
- problem it solves
- when to use
- steps
- example in the user's project world
- misuse warning
- related concepts

### Project Triggers

Each trigger must include:

- situation signal
- book idea to recall
- recommended action
- boundary or false positive
- output artifact

### Decision Checklist

Each checklist must include:

- decision context
- questions to ask
- evidence to gather
- red flags
- what the book would recommend
- when to ignore the book

### Obsidian Nodes

Prefer modular files:

- whole-book map
- chapter lectures
- concept cards
- method cards
- project triggers
- future expansion

## Compatibility

This bridge can reuse outputs from a `book-to-project-mastery` style workflow:

- three-layer summary
- transferable kernel
- concept internalization cards
- thinking framework transfer
- project trigger taxonomy
- method cards
- misuse boundaries

Do not duplicate these outputs if they already exist. Link and extend them.
