# Professor Book Skill

### 让 agent 先通读整本书，再像一位亲切的教授，从全书高处带你从 0 学懂它。

想象这样一种读书方式：

你把一本完全陌生的书、一份复杂报告、一篇论文或一套课程材料交给 agent。  
它不是马上给你一页摘要，也不是生成一堆需要你自己啃的拆书笔记。  
它先通读、抽取、建模整份材料，理解全书结构、章节关系、核心概念、论证脉络、领域背景和应用边界。

然后，它像一位已经把这本书读透的长者或教授，站在全书全局和完整脉络的高处，亲切地对你说：

> 我们先不要急着钻进细节。  
> 这本书真正要解决的问题是……  
> 全书可以先看成几层……  
> 你从 0 开始学，最快的路径应该这样走……

这就是 Professor Book Skill 想实现的体验。

它不是“读完以后帮你总结一本书”的 skill。  
它是“当你还没读过这本书时，让 agent 先读透，再陪你一步一步学懂，并把学到的方法沉淀成未来可复用能力”的 skill。

## 一句话

Professor Book Skill 是一个面向书籍和长文档的教授式带学元技能：它让 agent 先建立全书模型，再根据材料类型选择教学策略，在真实对话中从 0 教你学习，并把书中的方法论继续沉淀为可复用 skill、方法卡、项目触发器和行动清单。

## 为什么会有这个需求

很多人并不缺“书籍总结”。

真正的问题是：总结经常不能让人学会。

你可能遇到过这些情况：

- agent 生成了一份很完整的摘要，但你看完还是不知道这本书的全局结构
- 拆书文档很多，像预习资料，读起来很累
- 核心观点被提炼出来了，但章节之间为什么这样安排、概念为什么这样递进，仍然不清楚
- 方法论被提炼成 skill 了，但你自己其实没真正学过这套方法，不知道什么时候该用、怎么用、边界在哪里
- 读书笔记、摘录、清单和知识库越积越多，却很少真正进入你的行动和判断

这说明问题不只是“有没有总结”，而是缺少一个学习过程。

一个完全没读过书的人，最需要的不是更多压缩材料，而是有人已经站到全书高处，把整本书看明白，然后从 0 带他走一遍：

- 先看全书要解决什么问题
- 再看作者为什么这样组织内容
- 再看概念之间怎么依赖
- 再看哪些章节是承重结构
- 再看哪些细节可以先放一放
- 最后看这些知识怎么迁移到自己的项目、决策和实践里

Professor Book Skill 就是为了补上这一段。

## 和已有项目的关系

这个 skill 受到三个方向的启发，但关注点不同：

- **Cangjie Skill** 强调把书、长视频、播客等高价值内容中的方法论蒸馏成可调用的 AI Skills。它关心“读完、看完、听完之后，带走一套能调用的方法论”。
- **book-to-skill** 强调把技术书、文档集合或资料源转成结构化 agent skill，让 agent 在工作中按需读取章节、框架、术语和规则。
- **Professor Synapse** 强调一个智慧向导先收集上下文，再召唤合适专家，提供有目标、有步骤的指导。

Professor Book Skill 想补的不是这些能力的替代品，而是它们中间缺的一段：

> 在方法论被蒸馏成 skill 之前，用户本人能不能被一位“已经读完整本书的教授”带着真正学懂这本书？

也就是说，它更关注“学习发生的过程”。

它既不是单纯总结，也不是直接生成方法论 skill，而是先让 agent 化身教授，把书从全局、脉络、概念、论证、例子、边界和应用场景上讲给用户听。用户真正学过之后，再把书中的方法论沉淀成可复用 skill，价值会更大。

因为这时你不只是“拥有了一个 skill”，你还知道它从哪里来、解决什么问题、什么时候该用、什么时候不该用。

## 它想解决的痛点

### 1. 摘要太像“知道”，不像“学会”

摘要会告诉你一本书讲了什么，但很少带你经历理解过程。  
Professor Book Skill 要求 agent 从全书问题开始讲，逐步解释结构、概念、论证和应用，让用户真的跟上。

### 2. 拆书文件太多，主体验却很弱

很多拆书流程会生成全书地图、章节总结、概念卡、行动清单。  
这些文件有用，但如果它们变成主体验，用户仍然是在读资料。

这个 skill 把文件降级为 sidecar：它们用于预习、复习、查阅和沉淀；真正的主体验是在对话中教授。

### 3. 新手缺少“全书高处”

没读过一本书时，最难的是不知道什么重要、什么可以暂缓、概念之间怎么连接。  
Professor Book Skill 会先建立全书模型，再提供 `A. 高处总览` 或 `B. 从0一步步学习` 两种入口。

### 4. 不同材料不能用同一种讲法

理论书、实操手册、研究论文、行业报告、技术规范、课程材料，不应该被同一种模板处理。  
这个 skill 要求 agent 先判断内容类别，再动态决定教学风格、进度单位、讲解密度和输出形式。

### 5. 方法论 skill 需要“学过的人”才更会用

一本书可以被蒸馏成 skill，但如果用户没有经历学习过程，就容易把 skill 当成黑盒。  
Professor Book Skill 希望先带用户学懂，再沉淀方法论。这样用户和 agent 都知道这个 skill 的来源、边界和最佳使用场景。

## 它是怎么做的

Professor Book Skill 的流程可以理解为六步。

### 1. 先确认材料真的可读

agent 不能在没有可靠文本的情况下假装已经读完。

它会先检查来源：PDF、EPUB、DOCX、Markdown、论文、报告、手册、课程材料等。  
如果普通抽取为空、过短、乱码、缺少目录或章节结构，就进入 OCR/扫描件处理流程。

### 2. 通读并建立全书模型

正式教学前，agent 要先建立内部模型：

- 这份材料真正要解决什么问题
- 一句话主张是什么
- 全书可以分成哪几个部分
- 每章在整体中承担什么角色
- 核心概念之间如何依赖
- 作者的论证主线是什么
- 哪些例子承载了关键思想
- 哪些地方有边界、盲点或误用风险

没有这个模型，就不能声称“我可以从全书视角教你”。

### 3. 判断材料类型，选择教学策略

不同材料用不同讲法：

- 理论书：重概念依赖、问题意识和论证递进
- 实操书：重流程、决策点、错误模式和应用边界
- 研究论文：重问题、方法、证据、结论和局限
- 行业报告：重发现、趋势、数据口径和决策含义
- 技术规范：重结构、约束、接口、流程和实现风险
- 课程材料：重学习路径、练习顺序和掌握标准

进度也不是固定的 `1/15`。  
agent 会根据材料结构动态决定总段数：一本短报告可能是 6-10 段，一本密集教材可能是 30-60 段，一本实操书可能按工作流或方法模块拆分。

### 4. 让用户选择入口

教学开始前，agent 会问用户选择：

- `A. 高处总览`：先站在全书高处，讲清楚全书脉络、核心问题、主要部分、关键概念、学习路线和应用地图。
- `B. 从0一步步学习`：直接进入正式课程，从第一段开始带学。

如果用户完全陌生，默认更适合先走 A。  
如果用户已经了解主题，可以直接走 B。

### 5. 在真实对话中教授，而不是生成假课堂记录

这个 skill 明确禁止预生成“模拟课堂对话”。

教授过程应该发生在当前聊天里：

- agent 讲一小段
- 用户回复“继续”、提问或表达困惑
- agent 根据用户状态继续推进
- 每段都有轻量进度
- 学习状态可以写入 sidecar 文件以便下次继续

教学语气要像一位耐心的教授：先把当前内容放回全书脉络，再解释局部概念，最后告诉用户这一段真正要带走什么。

### 6. 学完后沉淀为可复用能力

如果用户需要，agent 可以继续生成：

- 全书脉络地图
- 学习路线与进度
- 章节复习
- 概念卡
- 论证链与证据
- 方法卡
- 项目触发器
- 决策检查清单
- 可转化为 skill 的方法论单元

这一步让学习不止停留在“我看懂了”，而是变成“我以后可以调用”。

## 核心特点

- **教授式带学，而不是摘要生成**  
  主体验是对话中的教授过程，不是让用户自己读一堆材料。

- **全书建模优先**  
  agent 先理解全书结构，再开始讲局部内容。

- **从 0 友好**  
  默认面向完全没读过这本书的人，先建立全局，再逐步进入细节。

- **快速但不丢深度**  
  它追求最快学习路径，但保留概念精度、论证关系、例子、边界和应用方式。

- **动态课程进度**  
  总段数来自全书结构和内容密度，而不是固定模板。

- **支持多种材料类型**  
  书籍、论文、报告、手册、规范、课程、访谈稿、长文档都可以进入同一套元流程。

- **sidecar 支撑材料**  
  静态文件用于复习和沉淀，不替代教授式学习。

- **方法论 skill 蒸馏**  
  学完后可以继续把书中的方法、流程、框架、检查清单和反模式沉淀成可复用 skill。

- **OCR 质量门控**  
  对扫描 PDF、图片型 PDF、乱码文本层，会先进行 OCR fallback 和质量检查。MinerU 可以作为可选解析路线，但必须先小样本验证。

- **agent-neutral**  
  不绑定某个具体 agent。只要能读取 `SKILL.md` 和相对目录资源，就可以迁移使用。

## 安装方式

把整个 `professor-book-skill` 文件夹放到你的 agent 支持的 skills 目录中。

常见位置：

```text
<agent-home>/skills/professor-book-skill/
<user-home>/.agents/skills/professor-book-skill/
<project-root>/skills/professor-book-skill/
<project-root>/.agents/skills/professor-book-skill/
```

然后这样调用：

```text
使用 professor-book-skill，从0开始带我学习这本书。
```

或者：

```text
使用 ./skills/professor-book-skill。先给我全书高处总览，然后再一步步教授。
```

## 适合场景

- 你面对一本完全陌生但重要的书，希望快速学懂
- 你不想只看总结，而想有人带着你从全书脉络学
- 你想把一本交易、商业、技术、设计、心理、管理或方法论类书籍变成自己的能力
- 你想学习一份长报告或论文，但不想丢掉论证主线
- 你想先真正学懂，再把方法论蒸馏成可复用 skill
- 你想让自己和 agent 的知识积累不断复利

## 设计信念

Professor Book Skill 背后的信念是：

> 好的 agent 不应该只是告诉你一本书讲了什么，而应该帮助你变成一个真正能使用这本书的人。

它希望把读书从“看总结”推进到“被带着学懂”，再推进到“把学到的东西变成以后可复用的能力”。

你越学习，agent 沉淀越多。  
agent 沉淀越多，你越知道怎么用。  
你和 agent 都在变强。

真正做到：学习没有白走的路，每一步都算数。
